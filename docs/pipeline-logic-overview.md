# パイプラインロジック概要

**対象ファイル**: `src/pipeline.py`  
**作成日**: 2026-04-19  
**目的**: チャンピオンズ対応の机上確認用

---

## 全体の流れ

```
フレーム取得（動画 or OBSカメラ）
  ↓
OCR実行（EasyOCR）
  ↓
フェーズ分類（BattlePhaseClassifier）
  ↓
イベント検知（フェーズ遷移 or メッセージパース）
  ↓
戦況更新（BattleStateTracker）
  ↓
Bedrock呼び出し → 実況文生成 → VOICEVOX音声合成
```

---

## 1. OCR テキスト抽出

| 項目 | 内容 |
|------|------|
| 関数 | `run_ocr(reader, frame)` |
| 出力 | `[{"text", "confidence", "bbox"}, ...]` |
| 変更点（2026-04-19） | `preprocess_hp=True` を削除。フルフレームOCRに統一 |

**注意点**
- 信頼度 `< 0.4` のトークンはほとんどの処理でスキップ
- hp_opp ROIだけ前処理する `preprocess_hp` オプションは残存するが、現在は使用しない

## 2. HP テキスト正規化

| 項目 | 内容 |
|------|------|
| 関数 | `_normalize_hp_text(t)` （`_extract_structured_info` 内ローカル関数） |
| O→0 | `O`, `o` を `0` に置換 |
| {→8 | `{` を `8` に置換（hp_opp1 で発生） |
| スラッシュ誤読 | `^(\d{1,3})[17](\d{2,3})$` にマッチ → `XX/YY` に補正 |
| 誤補正防止 | 補正後に分子 > 分母の場合はそのまま返す |

**例**
```
"1557155" → "155/155"  ✅（スラッシュが7に誤読）
"7681155" → そのまま   ✅（768 > 155 なので補正しない）
"{0%"     → "80%"      ✅
"8O%"     → "80%"      ✅
```

## 3. HP 分類（自分 / 相手）

| 条件 | 振り分け先 |
|------|-----------|
| `cy < _PLAYER_Y_THRESHOLD (500)` | 相手HP |
| `cy >= 500` | 自分HP |

**チャンピオンズ座標との整合性**
| エリア | y座標 | 判定 |
|--------|-------|------|
| hp_opp0/1 | 120〜170 | `< 500` → 相手 ✅ |
| hp_plr0/1 | 1000〜1050 | `>= 500` → 自分 ✅ |

**変更点（2026-04-19）**  
`elif cy < _COMMAND_Y_MIN (700)` → `else` に変更。以前は y=700〜1050 の自分HPが取りこぼされていた。

### HP% （相手専用・チャンピオンズ）
- パターン: `(\d{1,3})%`
- `pct_val <= 100` のみ有効
- `cy < 500` の場合のみ相手HPとして登録

## 4. ポケモン名分類

| 条件 | 振り分け先 |
|------|-----------|
| `cy < 500` | 相手名候補 |
| `cy >= 500` | 自分名候補 |
| `cy > _COMMAND_Y_MIN (700)` かつ PokeClassifier なし | 除外（コマンドメニュー誤検知防止） |

**チャンピオンズ座標との整合性**
| エリア | y座標 | 判定 |
|--------|-------|------|
| name_opp0/1 | 50〜90 | `< 500` → 相手 ✅ |
| name_plr0/1 | 930〜970 | `>= 500` → 自分 ✅（PokeClassifier 有の場合） |

**PokeClassifier なし時の注意**  
`cy > 700` フィルターにより、自分ポケモン名（y=930〜970）が除外される。  
→ チャンピオンズでの動作確認は PokeClassifier あり前提で行うこと。

---

## 5. フェーズ分類（BattlePhaseClassifier）

優先度順に判定:

| 優先度 | フェーズ | 検出キーワード |
|--------|---------|--------------|
| 1 | `battle_end` | 勝負に勝/負・降参・通信エラー |
| 2 | `selection_screen` | ポケモンを選んで・選出・きめる |
| 3 | `faint` | `0/XX` or `0%`（HP=0パターン） |
| 4 | `switch_select` | こうたい・ポケモンをえらんで |
| 5 | `command_select` | たたかう・どうする・ゆけつ |
| 5' | `command_select` | こうかあり（技選択UI継続） |
| 6 | `animation` | バツグンだ・きゅうしょ・ひんし |
| 7 | `unknown` | 上記なし |

**チャンピオンズ確認ポイント**  
- `faint` 検出: `0%` パターン対応済み（`_HP_ZERO_RE`に`\b0%\b`を含む）
- `command_select` KW: `たたかう` など変更なしのはず

---

## 6. イベント検知（BattlePhaseClassifier.detect）

フェーズ遷移でイベントを発火:

| 遷移 | イベント | デバウンス |
|------|---------|-----------|
| 初回 `command_select` | `battle_start` / `turn_start` | 15秒 |
| `command_select` → 他 | `move_used` | 15秒 |
| `switch_select` 出現 | `switch` | 10秒 |
| `faint` 出現 | `faint` | 25秒 |
| `battle_end` 出現 | `battle_end` | — |

---

## 7. メッセージパース（BattleMessageParser）

メッセージボックスROI（`x=120〜900, y=740〜930`）のテキストを解析。

| 検出 | パターン | イベント |
|------|---------|---------|
| 気絶 | `(.{2,12})(?:は\|が)\s*たおれた` | `faint` |
| 自分繰り出し | `ゆけ` 系 or `とびだした` | `switch_in` |
| 相手繰り出し | `(.+)を\s*く[りゆ]だした` | `switch_in` |
| 交代 | `もどれ〜` or `〜こうたいした` | `switch_out` |
| 状態異常 | `〜は まひ/やけど/どく...` | `status` |

**チャンピオンズ確認ポイント**  
- MSG_X_MAX を 520→900 に拡張済み（メッセージが画面中央まで広がる）
- `く[りゆ]だした` でOCR誤読（り→ゆ）に対応済み

---

## 8. 技ログ更新（_update_move_log）

`PipelineRunner._update_move_log()` で技を検出・登録。

### スキャン順序

1. **スキャン1「の/は」**: OCRトークンを走査
   - `Xの` → 直後トークンを技名候補
   - `Xは` → 後続4トークンウィンドウを技名候補
   - `_MOVE_ALIAS_MAP`で変形表記を正規技名に変換

2. **スキャン2 ROI**: メッセージボックス結合テキストに `_MOVE_IN_MSG_RE` 適用

3. **dense scan**: 技検出後 最低90フレーム維持（ターン継続中の再スキャン）

### 後付け修正
- フォールバック仮確定エントリを `_tentative_opponent_moves` で追跡
- 次のメインOCRで正しい使い手を確認したら上書き修正

---

## 9. switch-in 検出

`_OPPONENT_SWITCH_IN_RE` で相手の繰り出しを検出:
```python
r'(?:[^\s]{2,12}と\s*)?(?:[^\s]*は\s*)?([^\s]{2,12}?)を\s*く[りゆ]だした'
```

**チャンピオンズ確認ポイント**
- 未検証: チャンピオンズでの `くりだした` テキストが同じ表記かどうか要確認

---

## 10. 特性・道具発動検出（_scan_ability_msg）

| エリア | 座標（1920x1080基準） | 対象 |
|--------|----------------------|------|
| `ability_msg_player` | x=0〜555, y=450〜570 | 自分側 |
| `ability_msg_opp` | x=1365〜1920, y=450〜570 | 相手側 |

OCRトークンの中心座標をスケール補正後にエリア判定し、テキストをbucketに蓄積。

---

## 11. 状態異常同期（_sync_status_from_ocr_bbox）

OCR bbox の x座標でスロット（0/1）を判定し、`BattleStateTracker` に反映。

| 状態異常テキスト | 対象スロット判定 |
|----------------|----------------|
| まひ・やけど・どく等 | x座標でスロット0（左）/1（右）を推定 |

---

## 12. 戦況トラッカー（BattleStateTracker）

場の状態を管理するクラス。

| フィールド | 内容 |
|-----------|------|
| `_player` | 自分の場の2匹（`FieldPokemon` リスト） |
| `_opponent` | 相手の場の2匹 |
| HP | `hp_pct_pixel`（ピクセル解析）または OCR文字列 |
| 状態異常 | `status` フィールド（まひ・やけど等） |
| 技 | `per_pokemon_moves` |
| 気絶 | `is_fainted` フラグ |

---

## 13. ピクセルHP解析（hpbar_analyzer）

`update_pixel_hp()` でHPバーの色から残量%を推定。

- 自分HP: ピクセル解析と並行してOCRも実施
- 相手HP: OCRでは取れない場合のメイン手段（`HP:46%(px)` 表示）

---

## 14. Bedrock呼び出し（_call_bedrock_vision）

| トリガー | 条件 |
|---------|------|
| `move_used` | コマンド確定後 |
| `faint` | 気絶検知（保留→`move_used`と統合する場合あり） |
| `battle_end` | 試合終了 |

T4ターン分割対策: `_pending_faint_state` で faint 送信を保留し、12秒以内に `move_used` が来たら統合して1回送信。
