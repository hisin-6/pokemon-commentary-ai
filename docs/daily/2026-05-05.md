## 実施内容

### 1. BattlePhaseClassifier 根本改修 (`src/pipeline.py`)

**問題**: ダブルバトルで2匹目コマンド入力時にも `command_select` が発火 → `move_used` が誤発火していた。

**修正**:
- `communication` フェーズを新設（「通信待機中」「通信中」テキスト検出）
- `move_used` を「communication → non-communication」遷移に変更
- `_allow_turn_start` フラグを追加し、`move_used` 後にのみ `turn_start` を許可 → 余分な `turn_start` を根本解決

**効果**: T1〜T7 全ターンが書き起こしと一致 ✅

---

### 2. dense scan を turn_start まで継続 (`src/pipeline.py`)

**問題**: dense scan が `move_used` 後 90 フレーム（約 54 秒）で打ち切られ、T6 ねっぷう等の遅延技テキストを取りこぼしていた。

**修正**: `move_used` 検知時に `_dense_scan_remaining = 9999`（実質無制限）に設定。`turn_start` / `battle_start` / `battle_end` でリセット。

**効果**: T6 ねっぷう・T7 アイアンヘッド等、アニメーション後の遅延テキストも確実に捕捉 ✅

---

### 3. まもる dense_scan バグ修正 (`src/pipeline.py`)

**問題**: 技ログに「まもる」が登録されると `_dense_scan_remaining = 90` で上書きされ、せっかくセットした 9999 が潰されていた。

**修正**: まもる専用分岐を削除し、単一ロジック `if self._dense_scan_remaining < 90: max(...)` に統一。  
9999 のときは何もしない（max で保護）。

---

### 4. switch_out「戻れ」検出修正 (`src/pipeline.py`)

**問題**: Champions 形式の交代メッセージ「オオニューラ\n戻れ！」（漢字）が `_SWITCH_OUT_RE` にヒットせず、自分ポケモンの退場が戦況に反映されなかった。

**修正**:
- `_SWITCH_OUT_RE` に `(\S{2,12})\s*戻れ` グループを追加（漢字対応）
- `_update_switch_out()` にパターン2を追加: 「戻れ」トークンの直前 4 トークンを PokeClassifier でスキャン → pokemon 名を特定して `mark_bench_by_name()` 呼び出し
- `_handle_message_event` の `switch_out` 処理にも PokeClassifier 正規化を追加

---

### 5. 同名ポケモン誤 faint 修正 (`src/pipeline.py`)

**問題**: 相手のドドゲザンが倒れた際、「ドドゲザン は たおれた」と「相手の」プレフィックスなしで誤 OCR → 自分のドドゲザンが誤って気絶扱いになっていた。

**原因**: `_FAINT_RE` が「相手の」プレフィックスを捕捉しておらず、`confirm_faint_by_name` が両サイドを検索していた。

**修正**:
- `_FAINT_RE` の group1 で「あいて / 相手の」プレフィックスを捕捉
- `BattleMessageParser.parse()` で prefix の有無により `faint` / `opponent_faint` に分岐
- `BattleStateTracker` に `confirm_player_faint_by_name` / `confirm_opponent_faint_by_name` を追加（片側のみ検索）
- `_handle_message_event` でそれぞれを呼び分け

### 6. T1 開始時プテラ欠け修正 (`src/pipeline.py`)

**問題**: battle_start OCR のタイミングではコマンド選択画面（1匹目のオオニューラのみ表示）になっており、プテラが映らなかった。その後のターンでも技アニメーション中はポケモン名が映らず、プテラが場(自)に登録されないまま推移していた。

**修正（3層）**:

1. **`_pre_battle_player` キャッシュ**: battle_start 前の OCR で `ゆけ\S*\s+(\S{2,12})` パターンを検出し、PokeClassifier で正規化してキャッシュ。battle_start 時に `mark_on_field_by_name()` で登録。

2. **`accumulate_player_name()` メソッド**: `BattleStateTracker` に追加。定期 OCR で `_extract_structured_info` を実行し、y 座標分類で自分側ポケモン名を蓄積。ターゲット選択画面等で両ポケモンが映った時点で捕捉できる。
   - 相手側登録済み名はスキップ（誤分類対策）
   - ダブルバトル上限（場 2 匹）超えは追加しない

3. **battle_start フォールバック対応**: `_pre_battle_player` を遅延起動パスでも登録。

**期待ログ**: `[事前検出] 自分 プテラ（ゆけっ！検出）` または `[戦況] プテラ 定期OCR検出 → 新規登録して場に追加`
