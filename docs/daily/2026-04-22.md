# 日報 2026-04-22

## やったこと

### 1. HP異常値フィルター追加 ✅
- **問題**: `787/201`（787 > 201）のような OCR 誤読値が戦況に入っていた
- **原因**: `_normalize_hp_text` の `if cur <= mx` は正規化するかどうかの判断であり、弾く機能ではなかった
- **修正**: `hp_pattern.search` マッチ後に `cur_val <= denom` チェックを追加
  - `src/pipeline.py` `_extract_structured_info` 内 hp_pattern マッチ後

### 2. HPpx優先・OCRフォールバック ✅
- **問題**: `_format_pokemon` で OCR HP が優先され、HPpx（ピクセル解析値）が表示されなかった。2匹に同じ OCR HP 値が入る問題も発生。
- **修正**: `p.hp_pct_pixel is not None` なら `HP:XX%(px)` を表示し、OCR は `elif p.hp` のフォールバックに格下げ
- **効果**: スロット固定のピクセル計測が主力になり、2匹の HP が独立して表示される

### 3. COMMAND bbox 座標収集スクリプト作成 ✅
- **ファイル**: `scripts/detect_command_bbox.py`
- 動画からCOMMAND系テキスト（OCR誤読含む）を検出し、bbox中心座標を CSV に出力
- 出力カラム: frame, time_sec, text, conf, cx, cy, x1, y1, other_texts
- `logs/command_bbox_20260422_220603.csv` で確認 → cy=377（行動/技選択）と cy=129（対象/交換選択）の2パターンを確認

### 4. COMMAND cy座標によるOCR HPセット制御 ✅
- **背景**: cy=377 の画面（たたかう/こうたい選択・技選択）ではHPが表示されるのでOCRセット有効。cy=129 の画面（技対象選択・交換選択）やアニメーション中はHPpxに任せる。
- **実装**:
  - `_extract_structured_info` でCOMMAND テキストを検出し `command_cy` を取得
  - `_build_game_state` 経由で `BattleStateTracker.update()` に渡す
  - `_CMD_CY_MIN=300, _CMD_CY_MAX=450` の範囲内のみ `_assign_hp_by_slot` を実行

### 5. `_assign_slot_indices` 空きスロット割当修正 ✅
- **問題**: イダイトウが早期割当で slot_0 取得済みの状態で、オオニューラ（候補1匹）も slot_0 に割り当てられていた
- **修正**: 候補1匹・空きスロット1つの場合は、既に使われているスロットを除いた空きスロットに割り当てる
- **検証**: 次回 Champions 動画ログで確認予定
