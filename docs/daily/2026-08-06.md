### データウェアハウス記録バグを発見・即日修正

壁の実機検証中のログ（`logs/pipeline_20260806_225851.log`）に
`戦況ウェアハウス記録エラー: Error binding parameter 14: type 'list' is not supported`が
試合中ずっと連発しているのを発見。

- **原因**: `_record_situation_snapshot`（`src/pipeline.py`）が`hp_player`列（TEXT）に
  `game_state["hp_values"]`（list型・しかも自他混在の生データ）をそのまま渡していた。
  sqlite3はlistを直接バインドできずINSERT自体が毎回例外→`try/except`で握りつぶされ実況には
  影響しないため気づかれていなかった。08-04の実装完了以降、**一度も記録に成功していなかった**
- **修正**: 自他分離済みの`hp_player_by_slot`/`hp_opponent_by_slot`（list[str]）を文字列結合
  してから渡すよう変更。常に`None`固定だった`hp_opponent`列も正しく埋まるよう修正
- 単体テストが`hp_values`を文字列でモックしていて実態と不一致だったため検出できていなかった点も
  修正（実データ形状=listでのテストケースに更新＋回帰テスト追加）
- WSL pytest 674件全パス（既存673件＋新規1件）。**EC2再デプロイ不要**（ローカルpipeline.py側のみ）。
