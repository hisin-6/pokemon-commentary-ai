# ゲームAI自作 - 別プロジェクト検討メモ

- **作成日**: 2026-08-06
- **経緯**: ローカルLLM移行（改善ロードマップ⑦）の話題の延長で、「言語モデルを0から作れるか」
  「囲碁・将棋のようなゲームAIを0から作れるか」を雑談的に相談・調査した。
- **結論（ユーザー決定）**: 本プロジェクト（ポケモン対戦実況AI）とは**別立ての新規プロジェクト**
  として実施する。位置づけは「本プロジェクトの強化のための研究・学習プロジェクト」。
  着手時期・①②どちらを先にやるかは未定（このセッションでは方向性の相談のみで、実装は未着手）。

## 1. LLMを0から作れるか

| 区分 | 現実味 |
|---|---|
| 教育・学習目的のミニGPT（nanoGPT等、数百行のTransformer実装をランダム初期化から学習） | ✅ RTX 3080 10GBで実現可能。小説やWikipedia抜粋等、数百MB〜数GB規模のデータで数時間〜1日程度 |
| 実用レベル（gemma2:9b級ですら）のLLMを0から学習 | ❌ 非現実的。学習データは数兆トークン規模、計算資源は数千〜数万GPU・日、コストは数億〜数十億円規模が必要 |

RTX 3080 10GBだと9B級モデルの**推論**すらギリギリで、ファインチューニング（既存モデルの重み調整）
の可否すら情報源で割れる状況（[[project_local_llm_finetuning]]参照）。ゼロから学習となると
桁が2〜3個足りない。

**このプロジェクトへの結論**: 実況AIの用途では「0から作る」よりRAG（プロンプトに事実注入。
type_hint/condition_hint等ですでに実施済み）＋既存モデルへのファインチューニングの方が
圧倒的にコスパが良い。この結論は既存の[[project_local_llm_finetuning]]と一致。

## 2. ゲームAI（囲碁・将棋型）を0から作れるか

LLMと違い、こちらは**個人でも本当に強いものが作れる領域**。理由は自己対戦で学習データを
無限に自己生成できるため（LLMのように外部から兆トークン規模のテキストを集める必要がない）。

### 基本構成（AlphaZero方式）
- **方策・価値ネットワーク（NN）**: 局面から「どこに打つべきか」と「勝率」を予測
- **モンテカルロ木探索（MCTS）**: NNの予測をガイドに有望な手を先読みして絞り込む
- **自己対戦強化学習**: NN vs NNで大量に自己対戦→勝った手を正解として学習し直す、を反復

### 規模による現実味

| 規模 | 現実味 | 目安 |
|---|---|---|
| 本家AlphaZero級（囲碁19路盤フル・超人級） | ❌ 個人には無理 | 当時TPU数千台×数日、学習コストのみで数億円規模 |
| OSS再現（Leela Zero等） | △ 個人では厳しい | 世界中のボランティアがGPU持ち寄って数年がかり |
| 小盤面・簡易ゲーム（9路盤囲碁、五目並べ、コネクトフォー等）のAlphaZeroクローン | ✅ RTX 3080 1枚で現実的 | 数日〜数週間の自己対戦学習で初心者〜中級者級を狙える |
| 将棋の伝統的アプローチ（NNUE評価関数＋αβ探索） | ✅ 個人で現実的 | 「やねうら王」等OSS将棋エンジンの評価関数を自作学習させる方式。GPU1枚で数日〜数週間 |

### 手順（小盤面AlphaZeroクローンの場合）
1. **ゲーム環境の実装**: 盤面表現・合法手判定・勝敗判定をコード化。バグがあると学習全体が
   崩れるので最初にテストを固める。小盤面（9x9囲碁、五目並べ、コネクトフォー等）から始めるのが現実的
2. **NNの設計**: 盤面をテンソル化してCNNへ。方策ヘッド＋価値ヘッドを1本のネットワークで同時出力
3. **MCTS実装**: NNの予測をガイドに有望手を優先的に深読みする探索
4. **自己対戦でデータ生成**: 現状NN＋MCTSで自己対戦を大量実行、各局面の「MCTSの読み分布」と
   「勝敗」を記録
5. **学習**: フェーズ4のデータでNNを再学習
6. **評価して入れ替え**: 新NN vs 旧NNで対戦させ、明確に勝ち越したら最強モデルを更新
7. **3〜6を反復**: 1サイクル（自己対戦→学習→評価）を何十〜何百周も回す

使用ツール: PyTorch＋既存OSS`alpha-zero-general`（ルール実装を差し替えるだけで着手可能）。

## 3. ポケモン対戦AI（不完全情報＋乱数ゲーム）を0から作れるか

囲碁・将棋との決定的な違い:
- **不完全情報**: 相手の控えポケモン・正確な努力値/個体値・持ち物が試合中わからない
- **確率要素**: 命中率、乱数ダメージ幅、急所、追加効果発動率

このためAlphaZero方式（完全情報のMCTS）はそのまま使えず、ポーカーAI等で使われる
不完全情報ゲーム向け手法（CFR＝反実仮想後悔最小化、情報集合サンプリング等）が必要になる、
①より技術的難度が高い研究テーマレベルの領域。

### 手順
1. **バトルシミュレータの用意**: 自前でフルスクラッチは非現実的。Pokemon Showdownの
   バトルシミュレータをPythonから叩ける`poke-env`（OSS）が定番の出発点
2. **状態表現の設計**: 見えている情報だけで特徴ベクトルを設計（ここが囲碁と根本的に違う難所）
3. **アルゴリズム選択**:
   - A. 強化学習（PPO等）: `poke-env`はGym形式インターフェースがあり、Stable-Baselines3等の
     既存RLライブラリと繋ぎやすい。初挑戦ならこちらが現実的
   - B. 探索ベース: 相手の見えない情報をランダムサンプリング→仮定ごとに完全情報探索→
     平均を取る力技（ポーカーAI的発想）
4. **自己対戦学習**: 自分自身の過去バージョンやShowdown組み込みAIを相手に大量対戦
5. **評価**: 既存の強いボットと対戦させ勝率で強さを測定

## 4. 必要リソース比較

| リソース | ①囲碁/将棋型（小盤面AlphaZero） | ②ポケモン対戦AI（poke-env+RL） |
|---|---|---|
| GPU VRAM | 1〜3GB程度 | 1〜4GB程度 |
| ボトルネック | CPU（MCTSシミュレーション計算） | CPU（バトルシミュレータ＝Node.jsサーバーの並列実行） |
| RAM | 通常のPC用途で十分 | 8〜16GB程度推奨（Node.js＋Python同時稼働） |
| ストレージ | 数百MB〜数GB（棋譜データ＋チェックポイント） | 数百MB〜数GB |
| 環境構築 | 1〜2日 | 1〜2日（Node.js＋poke-env導入） |
| 学習期間 | 数日〜数週間 | 数週間〜それ以上（①より難度が高い） |
| ソフトウェア費用 | 無料（PyTorch＋`alpha-zero-general`等OSS） | 無料（`poke-env`＋Pokemon Showdown battle-engine＋Stable-Baselines3等） |
| 知識面のハードル | 中（MCTS・強化学習の理解） | 中〜高（強化学習＋不完全情報下学習の理解） |

どちらもVRAM消費は1〜4GB程度で軽く、本体パイプライン（EasyOCR/YOLO/Bedrock等）のVRAM予算
（`.claude/skills/vram-budget/SKILL.md`）と本格的に競合する心配は薄い見込み。ただし同時稼働
させる場合はVRAM合計を都度確認する。

## 5. 結論・今後

- LLM自作は実況AI用途には不向き（既存結論どおりRAG＋既存モデルFTが本命）
- ゲームAI自作は「①小盤面の囲碁/将棋型AlphaZeroクローン」が最も取っつきやすく、
  「②ポケモン対戦AI」は本プロジェクトとの親和性は高いが難度も高い
- **本プロジェクトとは別の新規プロジェクトとして立ち上げる**（ユーザー決定）。位置づけは
  本プロジェクトを強化するための研究・学習用サブプロジェクト
- 着手時期・①②どちらを先にやるかは未定。着手判断時にこのドキュメントを起点にする
