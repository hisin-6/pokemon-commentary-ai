# RVC（声質変換）セットアップガイド

## 概要

くれぴの実況音声は、**VOICEVOX（読み上げ）→ RVC（声質変換）** の2段構成で作る方針（2026-07-21決定）。

```
実況テキスト → VOICEVOX（四国めたん・抑揚/間を担当） → RVC（声色をくれぴ用に変換） → 出力音声
```

- VOICEVOXが「何を・どう読むか」（抑揚・間・発音）を担当
- RVCは「どんな声色で聞こえるか」だけを変換する
- RVC変換後も**ベースにしたVOICEVOX話者の話し方の癖（抑揚・リズム）は残る**ため、話し方の雰囲気が近い話者を選ぶことが重要
- ベース話者は**四国めたん**に決定（「明るく元気」な声質でくれぴのキャラ性と相性が良いと判断）

フルTTS学習（Style-Bert-VITS2等）と比べて、RVCは**テキストと音声のペアデータが不要**（音声のみでOK）なため、録音素材調達のハードルが低い。

---

## 全体の流れ

```
① ITAコーパスを自分の声で録音（学習データ）
② RVC WebUIで自分の声モデルを学習（Train）
③ 自分の声モデルで試聴 → 必要ならピッチ等を調整
④ VOICEVOX（四国めたん）の出力を自分の声モデルで声質変換
```

**モデルマージ（Bモデルとのブレンド）は不採用に決定（2026-07-22）**。自分の声モデル単体をそのまま使う方針。検討したブレンド案の記録は末尾に残すが、実施はしない。

実行環境（RVC WebUI）はローカルに構築済み（過去に導入済み）。

## ① 録音：読む文章はITAコーパス推奨

「あみたろの声素材工房」や「つくよみちゃん公式サイト」で無料配布されている**ITAコーパス（全424文）**を使う。

- もともと**音声合成モデル・AIボイスチェンジャーモデル作成のために音素バランスを考慮して設計**された文章セット。自作台本より確実
- ノーマル版（感情なし・淡々と読む用）とエモーション版がある。まずノーマル版424文を通しで録音
- 全文読むと数十分〜1時間程度のボリュームになり、学習データとして十分
- 余裕があれば、実況で使いそうな語彙・テンション高めの掛け声を自分で追加録音すると実運用時の自然さが上がる（任意）

参考配布元:
- あみたろの声素材工房: https://amitaro.net/voice/corpus-list/ita/
- つくよみちゃん公式サイト（ITAコーパス収録＆配布者リスト）: https://tyc.rei-yumesaki.net/material/corpus/ita-list/
- GitHub（コーパス原本）: https://github.com/mmorise/ita-corpus

上記はどれか1つで足りる（内容は同じ）。

### GitHub版を使う場合のファイル選択

`mmorise/ita-corpus` リポジトリには複数ファイルがあるが、録音時に見るのは**`recitation_朗読者用.pdf`（または`.docx`）**でよい。

- 424文＝「recitation（朗読）324文」＋「emotion（感情）100文」の2セット構成。ノーマル版として使うのは**recitation（324文）**
- `recitation_朗読者用.pdf/docx` = 読み上げる人向けに整形された配布用ファイル（← これを見ながら読む）
- `recitation_transcript_utf8.txt` / `_ruby_utf8.txt` = 音声ファイル名と文章を紐付けるための機械可読データ（後工程用・録音時は見なくてよい）
- `emotion_*` = 感情版100文（今回は録音対象外）

### 録音のコツ

- **静かな環境**で録音（エアコン・PCファン音に注意。難しければ布団や毛布で簡易吸音するだけでも効果あり）
- マイクとの**距離を一定**に保つ（ポップガード推奨。口の真正面を避け斜め気味に構えるとポップノイズが減る）
- フォーマットは **WAV・44.1kHz以上・モノラル**（RVCの学習はモノラル前提）
- 音量は**クリッピングしない**ように、ピークに余裕を持たせる（目安-6dB程度）
- 疲れると声のトーンが変わるので、**短いセッションに分けて複数回録音**してもOK（むしろ推奨）
- 息継ぎ音・咳払い・リップノイズは気にせず録音を続け、後で気になる箇所だけカット編集でよい（多少のノイズは前処理側で吸収される）

### 噛んだ場合の対応

- **軽い言い淀み程度**: 気にせずそのまま読み進めてOK。ノイズと同様、前処理（無音区切りでのスライス）が吸収してくれる
- **はっきり噛んだ・言い間違えた場合**: 録音を止めずに、その場で同じ文をもう一度読み直せばよい。ファイルを破棄する必要はなく、編集時にその区間だけカットすればいい（前処理はどのみち音声を短い区間に自動スライスするため、1文単位の修正は容易）
- **録り直すべきケース**: 咳き込み・環境音混入・声が裏返る等、セッション全体の質が落ちた場合のみ、そのセッションを録り直す
- 完璧を求めて何度もやり直すと疲れて声のトーンが変わる方が問題なので、多少の噛みは気にせず量をこなす方を優先する

### ファイル分割（1文ごと・1分ごと）は必要？

**不要**。RVCの前処理（スライス工程）は無音区間を検出して自動で短い区間に分割してくれるため、1文ごとや1分ごとに手動でファイルを分ける必要はない。まとめて長い1本の録音のまま渡してOK。

- フルTTS学習（テキストと音声の対応が必要な方式）では文単位でファイルを分けて transcript と紐付けることが多いが、**RVCはテキスト対応が不要な声質変換モデル**なので、そもそも文単位の紐付け自体が不要
- ファイルを分けるかどうかは録音のしやすさ・休憩のタイミングで自由に決めてよい（技術的な制約ではない）

- RVC WebUIの学習タブで、前処理（音声スライス・特徴抽出）→ 学習（epoch数設定）

## （不採用）モデルマージ（Bモデルとのブレンド）検討記録

⚠️**2026-07-22時点でマージは行わない方針に決定**。自分の声モデルをそのまま使う。以下は検討時の記録として残す。

RVC WebUIの**「ckpt処理」タブ**にモデル融合機能がある。

```
結果 = Aモデル × a + Bモデル × (1 - a)
```

- `a=1` でAモデル（自分の声）そのまま、`a=0` でBモデルそのまま、`a=0.5`で半々ブレンド
- 比率を変えながら試聴し、理想の声に近づける
- **融合には両モデルが同じアーキテクチャ・バージョン（v1/v2など）である必要がある**（異なるバージョン同士は融合不可）

### Bモデルの選定について

- **既存の配布済みRVCモデルを使う場合**: 商用利用（YouTube収益化）の可否を必ず規約で確認すること。配布モデルは非商用限定や利用規約付きのものが多い
- **自分で2本目のモデルを作る場合**: 声のトーンを変えて別バージョンを録音・学習すれば、権利関係をクリアにしたままバリエーションを作れる（推奨）

### 検討したが非推奨と判断した案: 動物の鳴き声をBモデルにする

猫の鳴き声などをBモデルの学習データにするアイデアを検討したが、以下の理由で非推奨と判断（2026-07-21）:

- RVCの特徴抽出器（HuBERT/ContentVec）は**人間の音声で事前学習**されており、動物の鳴き声は完全に未知データ（out-of-distribution）
- 学術研究でも「動物の声は音声変換モデルにとって未知データとして扱われる極端な条件（extreme condition）」と位置づけられており、専用の追加設計なしでは苦戦するケースとされている
- F0（ピッチ）抽出も人間の声域を前提にチューニングされているため、猫の鳴き声だと不安定になりやすい
- 実務上、十分な量のクリーンな動物音声データ（10〜50分目安）を集めること自体が困難

配布されている「猫声」系RVCモデルの多くは、実際には**人間が猫っぽく発声した音声**（「にゃーにゃー」等の擬声）を学習データにしている。猫っぽさを出したい場合は、本物の動物音声ではなく**自分で猫っぽい高め・鼻にかかった声色を意識して録音**し、それをBモデルにする方が現実的。

## 推論・パイプライン統合

- 自分の声モデルをRVCの**「モデル推論」タブ**（Inference・日本語UIの表記）に読み込む
- VOICEVOX（四国めたん・speaker=2）で生成した音声を入力として声質変換
- 声の高さが合わない場合はピッチ調整（pitch shift）で補正

### 推論パラメータ（2026-08-16実機確認・`i18n/locale/ja_JP.json`で文言を確認済み）

- **検索特徴率（Index Rate）**: 上げるほど自分のコーパスの声質特徴を強く引っ張ってくる。
  自分の声に近づけたい場合は高め（0.75〜1.0）から試す
- **保護値（Protect）**: ⚠️直感と逆の仕様。**0.5＝保護オフ**で、**上げる（0.5に近づける）
  ほどindexの効果が強まり自分の声に近づく**が、子音・呼吸音のアーティファクト（電子音の
  途切れ等）のリスクが増える。下げると保護は強化されるがindexの効果（＝自分の声への
  寄せ）が下がる
- **ピッチ変更（半音数）**: 変換元（VOICEVOX四国めたんは声が高め）と自分の地声の音域差が
  大きいと変換品質が落ちる（モデルが学習した音域から外れるため）。マイナス方向へシフトして
  自分の地声の音域に近づけるのが有効
- 上記3つを軸に、実際に聴きながら微調整する（**2026-08-16時点ではユーザーが後日実施予定・
  最適値は未確定**）

## 地雷リスト（2026-08-16・実際に踏んだもの）

RVC-WebUI本体（`Retrieval-based-Voice-Conversion-WebUI-main`）側の問題。AITuberProject
リポジトリとは別管理だが、次回同じ環境で学習する時のために記録しておく。

| 地雷 | 症状 | 対処 |
|------|------|------|
| `assets/pretrained_v2`が空 | 学習に必須の事前学習済みモデルが無く即失敗する | `tools/download_models.py`を実行（HuggingFaceから一括DL・数GB規模・要requests）。`assets/rmvpe`のrmvpe.pt本体・`assets/hubert`のhubert_base.ptも同スクリプトで揃う |
| `go-web.bat`が起動しない | 存在しない`runtime\python.exe`を参照（プリビルド版の同梱Python前提の設定が残っている） | `venv\Scripts\python.exe`を使うよう書き換える（GitHubから直接cloneした環境の場合） |
| `RuntimeError: use_libuv was requested but PyTorch was build without libuv support` | モデル学習が即クラッシュ（Windows版PyTorchがlibuv非対応なのに`torch.distributed`がデフォルトで要求） | `infer/modules/train/train.py`冒頭に`os.environ.setdefault("USE_LIBUV", "0")`を追加 |
| `AttributeError: 'FigureCanvasAgg' object has no attribute 'tostring_rgb'` | Epoch 1のTensorBoard画像出力でクラッシュ（新しいmatplotlibでAPI廃止） | `infer/lib/train/utils.py`の`plot_spectrogram_to_numpy`/`plot_alignment_to_numpy`を`buffer_rgba()`ベースに書き換え |
| モデル推論タブでインデックスの候補が出ない | 「特徴インデックスのトレーニング」を実行したはずなのに反映されない | `logs/<モデル名>/`に`trained_*.index`（中間・空のIVF構造）しか無く、`added_*.index`（実際に特徴ベクトルを詰めた実ファイル）が無い可能性が高い。RVC-WebUIは`trained`を含むファイル名を候補から**意図的に除外**する仕様。ブラウザのリロード/通信切れ等でインデックス作成が中断されると起きる。`total_fea.npy`があれば、`train_index()`と同じfaissロジック（trainしてadd）を直接実行して復旧できる |
