# パス1 無課金検証 NGパターン集約

各動画の `renders/<動画名>/review_checklist.md` で見つかったNG項目を横断的に
ここへ集約する。**この時点では修正しない・収集フェーズ**（2026-08-10〜）。
ある程度パターンが溜まってから、まとめて優先度をつけて対応する方針。

## 運用ルール

1. `review_checklist.md`でNGを見つけたら、下の表に1行追記する
2. 原因調査（`manifest.jsonl`/`timeline.jsonl`/`states.jsonl`を見て、構造化データ側が
   正しいか・生成テキスト側の問題かを切り分ける）をした上で「原因分類」を埋める
3. 同じパターンが複数の動画で再発したら「件数」欄が分かるよう備考に追記
4. `docs/manual/pass1-verification-video-list.md`の進捗と対になる記録

## 原因分類の凡例

| 分類 | 意味 |
|---|---|
| LLMハルシネーション | 構造化データ（move_log/type_hint等）は正確なのに、生成テキストがそれと矛盾する内容を作った |
| LLM作話（情報不足） | contextに該当情報が無い（None/空）状態で、LLMが架空の情報ででっちあげた |
| パイプライン検出漏れ・誤検出 | 状態抽出（OCR/トラッカー）自体のバグ。構造化データの時点で誤り |
| Phi-3固有の癖 | ローカルLLM特有の文体破綻・意味不明化等（Bedrockでは起きない可能性） |
| 複合 | 上記の組み合わせ（パイプライン側の既知の仕様上の制約がLLMの作話を誘発した等） |

## 傾向メモ（気づいたら随時更新）

- 2026-08-10時点、1本目（2026-04-13_06-22-25）で2件発見。いずれもPhi-3が
  「渡された情報が無い/不十分な箇所を、断定口調ででっちあげる」という共通の癖が見える
  （NG#1は事実と矛盾する断定・NG#2は情報空白を埋める架空の固有名詞）。
  件数が増えたら「情報が無い時は断定を避ける」ようなプロンプト側の安全策の要否を検討する
- 2026-08-10、2本目（2026-04-14_21-44-43）で3件発見。
  - **LLM作話パターンが再発かつ悪化**: `move_log`が空の状態で技名（こごえるかぜ）・使い手・
    対象の3点セットを丸ごと捏造。しかも連続する2イベント（move_used→battle_start）で
    ほぼ同内容を繰り返し生成しており、Phi3Clientの会話履歴（history）が捏造内容を
    連鎖させている可能性がある（要注視・件数が増えたら履歴機構の見直しも検討）
  - **新パターン: 試合開始直後のポケモン名誤認識**（今回はランクルス⇔オオニューラ）。
    LLMではなくパイプライン（OCR/分類器）側の問題。正式battle_start以降は自己修復するため
    実害は限定的だが、選出画面OCRの精度に既知の弱さがある可能性
  - **新パターン（軽微）: HP0%の検出漏れ**。気絶判定（ボール数推定）自体は正しいが、
    HPバーの0%表示は捕捉できていない。実害なしなので優先度は低いが件数を見て判断
